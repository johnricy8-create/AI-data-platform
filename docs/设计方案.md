# AI 电商数据中台 · 设计方案

> 状态：正式版已实现（React + FastAPI + SQLite + 智谱 GLM），6 个页面与 AI 报告闭环已跑通。
>
> 参考文档：`Ai数据中台.docx`；参考视觉：用户提供的「AI 电商数据中台」架构与仪表盘图。

---

## 1. 项目定位

面向电商运营场景的数据中台 MVP，完成一条真实可运行的闭环：

```
CSV / Excel 导入
  → 清洗、校验、去重
  → SQLite / PostgreSQL 入库
  → 统一指标计算
  → 经营概览与商品分析
  → AI 查数、归因、建议
  → 运营计划与人工确认
```

第一版使用模拟数据，不依赖真实平台授权接口；但所有指标由程序计算，AI 只负责解释和建议，不直接修改价格、库存或投放。

## 2. 已确认的技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | React 19 + TypeScript + Vite | 高保真还原参考图，适合多页面 SaaS |
| 样式 | Tailwind CSS + shadcn/ui | 统一设计 token，快速构建表格、弹窗、抽屉 |
| 图表 | Apache ECharts | 趋势、渠道、四象限、商品排行 |
| 状态与路由 | TanStack Query + React Router + Zustand | 服务端状态与少量 UI 状态分离 |
| 后端 | Python 3.12 + FastAPI + Uvicorn | 保留 Pandas / SQLAlchemy / LangGraph 能力 |
| 数据 | Pandas + SQLAlchemy 2.0 + Alembic | SQLite 开发，PostgreSQL 后续迁移 |
| AI | OpenAI 兼容 API + LangGraph + Pydantic | 默认适配 DeepSeek / 通义 / OpenAI |
| 测试 | pytest + httpx（前端可选 Vitest） | 指标口径、导入异常、API 契约 |
| 运行 | uv + npm；本地脚本 | 当前环境无 Docker，不依赖容器 |

**前端路线选择理由**：参考图的深色侧边栏、渐变 AI 卡片、多图表联动和聊天布局，Streamlit 很难稳定还原；FastAPI 则保留文档中的 Python 数据分析与 Agent 能力。

## 4. 数据模型

在第一版 6 张核心表基础上做必要增强：

| 表 | 作用 | 关键补充 |
|---|---|---|
| `products` | 商品主数据 | `sku`、`category`、成本价、售价、状态 |
| `orders` | 订单主表 | `paid_at`、`buyer_id`、状态枚举、优惠金额、退款金额 |
| `order_items` | 订单明细 | `refund_qty`、`refund_amount`，支持商品级退款率 |
| `traffic_daily` | 每日流量 | 访客、浏览量、加购数、支付买家数；`product_id` 可空 |
| `inventory` | 库存 | `safety_stock`、`lead_time_days` |
| `import_jobs` | 导入任务 | 成功/失败数、错误详情 JSON、文件哈希、原始路径 |
| `ai_reports` | AI 报告 | 问题、筛选范围、指标快照、结构化报告、模型、耗时、Token |
| `chat_sessions/messages` | 可选 | 保存对话历史 |

两个基础约定：

- 金额统一用整数「分」存储，展示层转元，避免浮点误差。
- 时间统一存 UTC，业务日按 `Asia/Shanghai` 聚合。

### 订单状态

`pending_payment`、`paid`、`shipped`、`completed`、`cancelled`、`refunded`、`partially_refunded`。

销售口径包含 `paid / shipped / completed / partially_refunded`，排除未支付与已取消。

## 5. 指标口径

| 指标 | 口径 | 关键约束 |
|---|---|---|
| 净销售额 | 支付金额 − 退款金额 | 与订单状态、日期、渠道同范围 |
| 订单量 | 去重订单数 | 与销售额同口径 |
| 客单价 | 净销售额 ÷ 订单量 | 分母为 0 返回空值 |
| 访客数 | 对应日期/渠道/品类访客求和 | 品类级流量需 `product_id` 有值 |
| 转化率 | 支付订单数（或买家数）÷ 访客数 | 分子分母同范围，页面标注口径 |
| 毛利额 | 净销售额 − 销售成本（含退款冲回） | 简化毛利，不含佣金/物流/广告 |
| 毛利率 | 毛利额 ÷ 净销售额 | 分母 0 保护 |
| 退款率 | 退款金额 ÷ 支付金额 | 或按订单数，二选一并固定 |
| 库存预警 | 库存 < 安全库存，或可售天数 < 7 | 可售天数 = 库存 ÷ 近 14 日日均销量 |
| 同比/环比 | （本期 − 对比期）÷ 对比期 | 同渠道、同品类、同口径 |

## 6. AI Agent 设计

### 工具（全部只读）

```text
get_kpis              经营核心指标
get_trend             日/周趋势与同比环比
get_channel_share     渠道销售占比
get_product_ranking   商品销量/销售额/毛利排行
get_product_diagnosis 单品诊断
get_inventory_risk    库存不足与可售天数
get_refund_analysis   退款趋势与商品退款率
build_action_plan     基于事实生成运营计划
```

### 工作流

```text
用户问题
  → 意图/时间/渠道/品类解析（Pydantic）
  → 信息不足则澄清，否则使用默认范围
  → 工具规划（白名单、只读）
  → 查询指标（SQL/Pandas）
  → 规则 + 对比分析
  → 结构化报告生成
  → 证据校验（每条结论引用 facts）
  → 保存报告 + 前端渲染
```

### 报告结构

- 核心结论
- 关键指标变化
- 数据依据（evidence_id）
- 可能原因 + 置信度
- 建议措施 + 优先级
- 需要补充的数据
- 免责声明

### 三个防护

1. **证据校验**：结论必须引用 `evidence_id`，后端校验引用存在，否则降级或重写。
2. **无 Key 降级**：未配置大模型时进入演示模式，用规则模板生成基于真实指标的洞察，界面明确标注。
3. **Prompt 注入防护**：商品名、文件名等只作为数据传入；工具不接受 LLM 生成的任意 SQL。

## 7. 页面信息架构

首版 6 个页面：

1. **经营概览**：KPI、销售趋势、渠道占比、热销商品、AI 建议、快捷问答。
2. **商品分析**：销售额/销量/毛利/退款率排行、销售-毛利四象限、低销量识别、库存预警、商品详情抽屉。
3. **销售分析**：日/周趋势、渠道对比、品类结构、订单状态漏斗、退款趋势。
4. **数据接入**：上传、模板下载、字段映射、校验结果、错误明细、导入历史、质量评分。
5. **AI 运营助手**：对话、建议问题、流式回答、结构化报告、证据面板、一键生成运营计划。
6. **报告中心**：历史报告、筛选、查看、导出 Markdown（PDF 后续）。

`用户分析`、`营销分析` 首版不做，等补齐 `buyer_id`、广告费用、流量来源后再上，避免展示没有数据支撑的页面。

## 13. 当前实现状态（2026-10-26）

已完成正式工程，不再是静态 Demo：

- 后端：FastAPI + SQLAlchemy + SQLite，启动时自动生成 75 天演示数据（约 5 万订单）。
- 前端：React + TypeScript + Vite + ECharts，6 个页面全部接入真实 API。
- AI：智谱 BigModel 已接入，主模型 `glm-4.7-flash`，自动降级 `glm-4.5-air` / `glm-4.6`；单模型 22 秒超时，实测 5-7 秒返回。
- Agent：LangGraph 编排意图识别 → 工具取数 → 规则分析 → 模型报告 → 证据校验。
- 数据接入：真实 CSV / Excel / Word / PPT / PDF 解析，订单 / 商品 / 流量 / 库存四类模板，行级错误与幂等写入；文档由 AI 抽取为结构化字段。
- 报告：AI 报告自动保存，支持 Markdown 导出。
- 测试：`uv run pytest` 5 项通过。
